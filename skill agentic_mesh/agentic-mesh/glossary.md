# Glossary: Agentic Mesh

Alphabetical index of key terms and concepts across all chapters of *Agentic Mesh* by Eric Broda & Davis Broda.

- **Agent** — An autonomous software entity powered by an LLM that perceives context, plans actions, utilizes tools, and pursues goals with minimal human intervention. (Ch 1, 4)
- **Agent Certification Badge** — Cryptographic proof stored in the registry showing that an agent passed automated security scans and regulatory compliance audits. (Ch 9, 12)
- **Agent Drift** — The gradual deviation of an agent's reasoning, accuracy, or cost profile over time due to shifts in data distributions or model updates. (Ch 13, 14)
- **Agent Factory** — A centralized, automated software delivery pipeline that turns business specifications into production-certified microagents. (Ch 14)
- **Agent Fleet** — A coordinated collection of specialized agents working together under shared domain context, policies, and operational objectives. (Ch 1, 7, 13)
- **Agent Marketplace** — An internal or cross-enterprise portal enabling developers and autonomous agents to search, evaluate, and invoke certified agents. (Ch 7, 8)
- **Agent Profile** — The public identity card of an agent in the Marketplace, displaying capabilities, schemas, latency, cost, and certification tier. (Ch 8, 9)
- **Agent Workspace** — A durable virtual collaboration room where multiple agents share state, inspect peer outputs, and coordinate collective tasks. (Ch 4, 5, 10)
- **Agentic AI** — Systems characterized by goal-directed behavior, proactive problem-solving, environmental perception, and reflective execution rather than passive prompt-response. (Ch 1, 2)
- **Agentic Maturity Curve** — Progression framework tracking enterprise evolution from isolated LLMs to workflows, standalone agents, fleets, and mesh ecosystems. (Ch 1, 2)
- **Agentic Mesh** — A decentralized, governed architectural layer enabling heterogeneous autonomous agents to discover, communicate, collaborate, and transact securely. (Ch 1, 7, 8)
- **Agentic Mesh Registry** — Authoritative central directory storing cryptographically verified metadata for all active agents, tools, policies, and workspaces. (Ch 7, 9)
- **AgentOps** — Operational discipline combining traditional DevOps with agent-specific telemetry: tracking prompt drift, latency, token costs, and tool success rates. (Ch 6, 14)
- **AI Workflow** — A structured, step-by-step process where LLMs and tools are orchestrated through predefined, programmatic code paths. (Ch 3)
- **Behavioral Monitoring** — Runtime analysis comparing an agent's real-time actions and tool call frequency against its registered baseline profile. (Ch 11, 13)
- **Blackboard Pattern** — Asynchronous multi-agent communication pattern where agents read and write state to a shared workspace whiteboard. (Ch 5, 10)
- **Candidate Pipeline** — Backlog of enterprise business processes evaluated for their suitability for autonomous agent automation. (Ch 15)
- **Context Engineering** — The architectural discipline of curating, formatting, pruning, and injecting relevant information into an LLM's prompt window. (Ch 4, 5)
- **Correlation ID** — Unique transaction token passed across all multi-agent messages and tool calls to correlate distributed logs into a unified trace. (Ch 10, 12)
- **Cost per Completed Mission** — Financial metric capturing total token, compute, and tool licensing cost required to achieve a discrete business goal. (Ch 13)
- **Dead-Letter Queue (DLQ)** — Dedicated message queue where malformed, unparseable, or repeatedly failing agent messages are isolated for human inspection. (Ch 10)
- **Determinism Boundary** — Architectural separation between strict deterministic code execution (validations, transactions) and probabilistic LLM reasoning. (Ch 3, 6)
- **Enterprise-Grade Agent** — An agent hardened with production-ready security (mTLS, RBAC), deterministic guardrails, structured observability, and continuous compliance. (Ch 1, 6)
- **Event Mesh** — Distributed messaging fabric (Kafka/RabbitMQ) routing events across cloud regions and organizational boundaries. (Ch 10)
- **Event Replay** — Capability to replay past interaction events through an agent to debug unexpected behavior or test updated prompts. (Ch 10)
- **Federated Fleet** — Independent, domain-specific fleets collaborating across business boundaries through standardized mesh contracts. (Ch 13, 14)
- **Fleet Factory** — Automated orchestration platform that composes multiple microagents into mission-ready fleets with automated integration testing. (Ch 14)
- **Fleet Leader** — Orchestrator agent responsible for receiving high-level fleet missions, assembling member agents, delegating subtasks, and aggregating results. (Ch 7, 13)
- **Fleet Manager** — A human business leader responsible for the business outcome, performance, cost, and compliance of a specific agent fleet. (Ch 13)
- **Goal-Oriented Agent** — Autonomous problem solver capable of self-directed task breakdown, dynamic planning, and adaptive tool selection. (Ch 5)
- **Golden Test Dataset** — Curated collection of edge-case scenarios, ambiguous prompts, and adversarial inputs used to benchmark agent reliability in CI/CD. (Ch 14)
- **Human-in-the-Loop (HITL)** — Architectural pattern embedding human oversight, pre-execution approval gates, or collaborative co-piloting into agent workflows. (Ch 8, 12)
- **Indirect Prompt Injection** — Vulnerability where an agent processes untrusted external content containing adversarial prompts that hijack execution. (Ch 11)
- **Microagent (Microservice Agent)** — An autonomous agent encapsulated within a standard microservice container, exposing standardized gRPC/REST endpoints. (Ch 1, 6)
- **Minimum Viable Mesh (MVM)** — The smallest footprint of mesh infrastructure needed to prove end-to-end multi-agent viability in production. (Ch 15)
- **Mutual TLS (mTLS)** — Two-way cryptographic authentication ensuring both calling and receiving microagents verify each other's identity before connecting. (Ch 6, 11)
- **Observer Agent** — Non-intrusive monitoring agent that audits compliance, tracks performance SLAs, and enforces safety guardrails in real time. (Ch 5, 13)
- **Parameter Substitution** — Runtime mechanism where an agent extracts variables from prior tool responses and injects them into downstream actions. (Ch 5)
- **Policy as Code (PaC)** — Declaring governance rules (spending limits, data privacy) in version-controlled declarative code (e.g., OPA / Rego). (Ch 12)
- **Quantum of Reuse** — The microagent conceived as the atomic, reusable building block of enterprise AI systems. (Ch 6)
- **Reflection Loop** — Iterative mechanism where an evaluator model checks candidate outputs against rubrics and forces refinement cycles. (Ch 3)
- **Reliability Triad** — Engineering approach for probabilistic systems: Task Decomposition + Deterministic Execution + Specialization. (Ch 6)
- **Replanning** — The ability of an agent to inspect a failed task execution, determine root cause, and formulate an alternative path forward. (Ch 4, 5)
- **Semantic Discovery** — Searching the registry using vector embeddings of agent descriptions and capabilities rather than rigid exact-match keywords. (Ch 9)
- **Seven-Layer Agent Trust Framework** — Layered governance architecture: L1 Identity, L2 Authorization, L3 Policy, L4 Explainability, L5 Observability, L6 Certification, L7 Governance. (Ch 12)
- **Simulation Agent** — Specialized agent for modeling scenarios, stress-testing workflows, and generating synthetic environments. (Ch 5)
- **Super-Context** — Accumulated cross-agent state maintained within a workspace allowing agents to grasp overall mission progress instantly. (Ch 5, 10)
- **Task-Oriented Agent** — Specialized agent designed for deterministic, bounded operations (data extraction, SQL execution). (Ch 5)
- **Trust Gap** — Hesitation of enterprise leaders to grant autonomous execution authority to LLMs due to opacity, hallucinations, and liability. (Ch 6, 12)
- **Zero-Trust for Agents** — Architectural doctrine assuming any agent can hallucinate, be compromised, or deviate; every action must be verified. (Ch 11, 12)
